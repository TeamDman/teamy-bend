## What works and what changed

The experimental Rust port provides checking and pure normalization, native CPU
execution, and C/JavaScript executable generation for a substantial supported
subset. Existing executable contracts include console IO, tasks, timers,
channels, environment, files and TCP/UDP. Strict proof evaluation is deliberately
separate from effectful execution. These capabilities do not establish full
library or whole-language compatibility; see the [implementation plan](implementation-plan.md).

Substantive cloud fixes include Linux portability, demand-preserving numeric
representation and work accounting, normalization sharing and named-call
reconstruction, constructor/import resolution, reusable-pattern/template parsing,
C ownership retention, literal readback and source-attributed diagnostics.
These repairs retain safety limits and targeted regressions. Recent array
batches add qualification and ownership controls; they did not demonstrate a
new production defect or change runtime code.

Five executable lanes mean native Rust, pinned upstream C, pinned upstream
JavaScript, port-generated C and port-generated JavaScript. Matching a small
fixture in those lanes does not establish universal parity. C comparisons use
upstream's O3 CPU profile; port C also retains strict compiler warnings.
